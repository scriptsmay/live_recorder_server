## 3. 实时日志查看（P2）

### 3.1 需求分析

**功能需求**：

- 用户可在浏览器中实时查看日志更新
- 支持自动滚动到最新内容
- 可手动暂停/恢复实时更新

**技术选型**：Server-Sent Events (SSE)

**选型理由**：

- 单向数据流，适合日志推送场景
- 自动重连机制
- 轻量级，无需额外依赖

### 3.2 架构设计

```
┌──────────────────┐    SSE连接    ┌──────────────────┐
│   前端浏览器      │◄─────────────►│   Express Server │
│  (EventSource)   │               │   (SSE Endpoint) │
└──────────────────┘               └─────────┬────────┘
                                             │ fs.watch
                                             ▼
                                       ┌──────────────┐
                                       │  日志文件    │
                                       └──────────────┘
```

### 3.3 API 设计

| 端点                | 方法 | 描述                             |
| ------------------- | ---- | -------------------------------- |
| `/api/logs/stream`  | GET  | 建立 SSE 连接，实时推送日志      |
| `/api/logs`         | GET  | 获取日志文件列表                 |
| `/api/logs/content` | GET  | 获取指定日志文件内容（支持分页） |

#### 3.3.1 GET /api/logs/stream

**请求参数**：
| 参数 | 类型 | 必填 | 描述 |
|------|------|------|------|
| file | string | 是 | 日志文件名 |
| tail | number | 否 | 初始获取的行数，默认 100 |

**响应格式**：SSE 事件流

```
event: log
data: {"line": "2024-01-01 12:00:00 GET /api/test 200 5ms"}

event: log
data: {"line": "2024-01-01 12:00:01 POST /api/notify/live_download 200 10ms"}
```

### 3.4 前端设计

**页面结构**：

- 左侧：日志文件列表（复用现有组件）
- 右侧：日志内容展示区域
  - 实时更新开关
  - 自动滚动开关
  - 日志内容（带语法高亮）

## 4. 日志搜索过滤 + 自动清理（P3）

### 4.1 搜索过滤功能

**功能需求**：

- 关键词搜索（支持正则）
- 时间范围过滤
- 日志级别过滤（若后续引入分级日志）

**API 设计**：

#### GET /api/logs/search

**请求参数**：
| 参数 | 类型 | 必填 | 描述 |
|------|------|------|------|
| file | string | 是 | 日志文件名 |
| keyword | string | 否 | 搜索关键词 |
| start_time | string | 否 | 开始时间（ISO 格式） |
| end_time | string | 否 | 结束时间（ISO 格式） |
| page | number | 否 | 页码，默认 1 |
| page_size | number | 否 | 每页条数，默认 50 |

**响应格式**：

```json
{
  "total": 100,
  "page": 1,
  "page_size": 50,
  "results": [{ "line_number": 100, "content": "...", "timestamp": "2024-01-01 12:00:00" }]
}
```

### 4.2 自动清理功能

**功能需求**：

- 按文件大小清理
- 按文件年龄清理
- 保留最近 N 个文件

**配置参数**（存储于 settings 表）：
| 参数 | 类型 | 默认值 | 描述 |
|------|------|--------|------|
| log_retention_days | number | 30 | 日志保留天数 |
| log_max_total_size | number | 500 | 日志总大小上限（MB） |
| log_max_files | number | 50 | 最大日志文件数 |

**实现策略**：

- 看门狗定时任务（每日凌晨执行）
- 按时间排序删除最旧文件
- 可手动触发清理

## 5. 虚拟滚动优化（P4）

### 5.1 需求分析

**问题**：当日志文件超大（>100MB）时，一次性加载会导致：

- 浏览器内存占用过高
- DOM 渲染缓慢
- 可能导致浏览器崩溃

**解决方案**：虚拟滚动（Virtual Scrolling）

### 5.2 技术方案

**方案选择**：自定义虚拟滚动实现（避免引入额外依赖）

**核心原理**：

1. 只渲染可见区域的日志行
2. 根据滚动位置动态计算需要渲染的行
3. 使用占位元素保持滚动条正确

### 5.3 实现要点

**后端支持**：

- 支持按行号范围读取日志
- 快速定位到指定行

**前端实现**：

```javascript
// 核心逻辑
function renderVisibleLines(scrollTop, viewportHeight) {
  const startLine = Math.floor(scrollTop / lineHeight);
  const endLine = Math.min(startLine + visibleLineCount, totalLines);
  // 只渲染 startLine 到 endLine 的内容
}
```

## 6. 技术风险评估

| 风险点         | 描述                     | 影响           | 缓解措施                              |
| -------------- | ------------------------ | -------------- | ------------------------------------- |
| SSE 连接断开   | 网络不稳定导致连接中断   | 日志更新延迟   | SSE 自动重连 + 断线重连时获取最新内容 |
| 大文件内存占用 | 超大日志文件导致内存溢出 | 服务端崩溃     | 按行读取 + 流式处理，不一次性加载     |
| 并发连接数     | 大量客户端同时连接       | 服务器资源耗尽 | 限制并发连接数，设置连接超时          |

## 8. 安全考虑

1. **路径遍历防护**：严格校验日志文件名，禁止 `..` 等路径跳转字符
2. **访问控制**：后续可考虑添加登录验证
3. **敏感信息过滤**：日志中不应记录密码、Token 等敏感信息
